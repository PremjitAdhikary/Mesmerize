Bee population has been in decline in certain parts of the world, especially wild bee species. Commercially managed bees are kept for honey production and not for pollination. This produces a problem as it can create significant impacts on agriculture and ecosystems.

One solution is artificial pollinators. Drones which mimic bee behaviour continue pollination. Of course we cannot have individual bee drones driven by humans, we need some sort of automated steering behavior. Once the swarm is released, we need localised search algorithms to guide the drones. This is a simulation for the same!

Controls

  • Select an environment for the simulation from the radio options
  • Click on Run Algorithm to, well, run the algorithm
  • When the algorithm runs, the environment options are disabled. On the other hand algorithm specific controls are enabled
  • You can end the algorithm run at any point. Doing so will disable algorithm specific options and enable environment selection
  • Algorithm specific controls are explained in their individual tabs

The Algorithms

Below we have a couple of approaches.

The original simulation was Smart Rockets by Jer Thorp to demonstrate Genetic Algorithm. I came across this on, guess what, a Daniel Shiffman video.

The original simulation has multiple Rockets where all Rockets are controlled by 5 thrusters which get placed at a random location and have a random power. Additionally, each Thruster has a random fire pattern. All of these combined allow the spacecraft to make flight maneuvers.

Instead of rockets, I have bees here. Instead of 5 thrusters and random power for each, I simplified them to just be a random force that will be applied to propel the bee forward, hopefully towards the target.

The way the algorithm works here is:

  • The genes in the DNA of the bee are all the forces that would be applied to the bee for the journey
  • Initial population has randomly generated DNA
  • Fitness of a bee determines how successful it was to reach the target:
    • The fitness score is inversely proportional to the distance of the bee from the target
    • Fitness score penalised if the bee has crashed into an obstacle or headed out of bounds (of the view port)
    • Fitness score is rewarded if the bee has reached the target
    • Fitness score is rewarded further depending on the length of the path to reach the target (the shorter the better
  • After calculating fitness, rank the population according to fitness
  • Use Elitism to select top few ensuring the best ones survive to the next generation (can be adjusted in the controls)
  • Use Fitness Proportionate Selection to generate a mating pool
  • For Crossover, select two parents at random, then select a mid point at random, fill the left and right side with genes from each of the parent
  • Mutation introduces variation where every gene has a chance of being mutated (can be adjusted in the controls)

Algorithm specific Controls

  • Adjust Mutation Chance to control mutation for next generation
  • Adjust Elitism to govern how many elites are selected for next generation
  • Adjust Speed to speed up the bees
  • The buttons enable to fast-forward through generations

A limitation I noticed while running the Genetic Algorithm is that once a path is found, visually even though I could see a better path available, the algorithm did not explore further. Even after Mutation Chance and Elitism were tweaked. But when I run the algorithm again, it would find the better path. Well, might not be the immediate next run, but it would, at some point.

In case of the environment with One Obstacle, either path (right or left) is a viable option, but once the algorithm reaches the target with one of them, the other path is never considered.

That's when it occurred to me. What if run I multiple instances of the algorithm at the same time? That would increase the search space and the output of one will not influence the others. Did I just come up with a new algorithm? Will I be writting a paper on this? My excitement was very short-lived as one google search later I was staring at Parallel Genetic Algorithm!!

Parallel Genetic Algorithm (PGA) is defined as an extension of the genetic algorithm that allows distinct subpopulations to evolve in different directions simultaneously.

In short, break the population into subpopulations, run GA on each of these population in a contained manner, then take the results from each of these sub populations to report back.

This is also known as island model.

In some variations, migration of a small subset of the population across the islands is also considered to add more variety for Crossover. This is not implemented in the solution here. Like I mentioned, I did not want the output of one to influence the others.
